# AtmoSound (Group Project - Submitting on behalf of Group)

A machine learning pipeline that takes a Google Maps venue link and generates a Spotify-style playlist matching the venue's atmosphere. Built for a Practical Applications of ML course.

[Streamlit Deployed URL](https://atmosound-eejsk4pwner3sfjdojyujg.streamlit.app/): https://atmosound-eejsk4pwner3sfjdojyujg.streamlit.app/ 

---

## What It Does

1. User pastes a Google Maps URL for a restaurant, bar, cafe, etc.
2. The system pulls venue data from the Places API (type, rating, price, reviews, boolean flags like "live music" or "outdoor seating").
3. A Ridge Regression model predicts a 7-dimensional audio profile for that venue (danceability, energy, acousticness, valence, instrumentalness, liveness, speechiness).
4. The predicted profile is matched against 112 genre centroids computed from Spotify data.
5. Songs are sampled from the closest genres, weighted by popularity, and ordered in an energy arc.

The output is a playlist of ~25 tracks plus a radar chart showing the predicted audio profile.

## Datasets

**Manhattan Places** — 4,484 venues scraped from the Google Maps Places API in April 2026. 41 columns: rating, price level, primary type (e.g. `italian_restaurant`, `coffee_shop`), neighbourhood, 18 boolean attribute flags, review summaries, and generative summaries. Boolean attributes have 50–73% missing values; missingness correlates with venue type.

**Spotify Tracks** — 114,000 tracks across 114 genres (1,000 per genre) from the Kaggle Spotify Tracks Dataset. Each track has 7 audio features computed by Spotify's API. After filtering out low-popularity tracks (< 10), 91,271 remain.

---

## Preprocessing Pipeline

Handled in `AtmoSound_Preprocessing.ipynb`. Steps:

1. Drop 3 fully-empty columns
2. Encode booleans as 1 / 0 / -1 (true / false / unknown)
3. Impute missing ratings with median (4.5)
4. Ordinal-encode price level (1–4) with a missing indicator column
5. One-hot encode neighbourhood (33 values) and primary_type (175 values)
6. TF-IDF on combined review + generative summaries → truncated SVD to 50 dimensions
7. Min-max normalize everything to [0, 1]
8. Construct pseudo-labels by mapping venue types → genre groups → mean audio profiles, modulated by boolean flags and price level
9. Stratified 80/20 train/test split, training further split 80/20 train/val (seed=42)

Final feature matrix: 4,484 venues × 279 features.
Target matrix: 4,484 venues × 7 audio dimensions.

---

## Models

All implemented from scratch with NumPy (no scikit-learn).

**Ridge Regression** — Closed-form solution with λ sweep over {0.001, 0.01, 0.1, 1, 10, 100}. Best λ = 0.1. This is the deployed model.

**Neural Network** — Two hidden layers (128 → 64), ReLU activations, sigmoid output, Adam optimizer. Grid search over learning rate, batch size, and dropout. Early stopping with patience=20. Slightly better on validation MSE but not by enough to justify the added complexity.

**K-Means** — Venue clustering with K selected by silhouette score. Each cluster gets the mean audio profile of its members. Used for interpretive analysis (venue archetypes), not deployment.

## Results (Test Set)

| Model | MSE | Cosine Similarity | Top-3 Accuracy | Top-5 Accuracy |
|-------|-----|-------------------|----------------|----------------|
| Ridge (λ=0.1) | 0.000281 | 0.9991 | 98.0% | 98.6% |
| Neural Network | 0.000255 | 0.9992 | 97.8% | 98.3% |
| K-Means (K=25) | 0.001184 | 0.9964 | 85.3% | 88.3% |
| Mean Baseline | 0.004124 | 0.9874 | 29.2% | 36.3% |

Ridge was selected for deployment using the three-tier decision procedure from the proposal: Top-5 accuracy within margin → cosine similarity within margin → practical tiebreaker (Ridge is simpler, faster, and directly interpretable).

## How to Run

### Prerequisites

- Python 3.10+
- `pip install numpy pandas streamlit requests`

### Generate Pipeline Artifacts (if not already present)

Run the notebooks in order:

```bash
jupyter notebook notebooks/AtmoSound_Preprocessing.ipynb   # run all cells
jupyter notebook notebooks/AtmoSound_ModelTraining.ipynb    # run all cells
```

This creates the `pipeline_artifacts/` directory with all serialized models and data.

### Run the Streamlit App

```bash
streamlit run app.py
```

You'll need a Google Maps Places API key stored in `.streamlit/secrets.toml`:

```toml
GMAPS_API_KEY = "your-key-here"
```

### Test the Pipeline Standalone

```python
from atmosound import AtmoSoundPipeline

pipeline = AtmoSoundPipeline("pipeline_artifacts")

result = pipeline.generate_playlist({
    "rating": 4.5,
    "price_level": "PRICE_LEVEL_MODERATE",
    "primary_type": "italian_restaurant",
    "neighbourhood": "West Village",
    "review_summary": "Great pasta and cozy atmosphere",
    "serves_wine": True,
    "outdoor_seating": True,
})

print(result["audio_profile"])
print(result["playlist"][["track_name", "artists", "genre"]].head(10))
```

## Known Limitations

- Pseudo-labels are constructed from the same `primary_type` feature that the model uses as input, which inflates evaluation metrics. The model is partially learning to invert its own labeling function.
- Boolean attribute coverage is low (27–51% known), so the model relies heavily on `primary_type` one-hot features. The ablation study confirms this: categorical features alone achieve 98.6% Top-5 accuracy, while booleans or text alone reach ~70–74%.
- The Spotify dataset is static (not connected to a live API), so the song pool doesn't update.
- Venues outside Manhattan may have neighbourhood values not in the training vocabulary, falling back to the zero vector for that feature group.
